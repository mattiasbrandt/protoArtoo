# The replayable sheet for the artoo-esp32 Console bench runbook (#216),
# commands only -- everything #216 lists that the Console Client's scripted
# mode (#264) can express. Transport under test is the UART0 bridge over
# USB-UART. Scope is Bench-Mode: nothing connected to the board (#216's own
# scope). On THIS board that also means the ESP32 is out of the Artoo PCB,
# because GPIO15 is shared with SBUS strapping and USB will not sync in the
# socket -- an artoo-esp32 wiring fact, not a posture, and it says nothing
# about firebeetle2 (CONTEXT.md "Bench-Mode", 2026-09-17).
# Human-only steps are `pause` directives; what a row is expected
# to answer stays on #216's own criterion, never written here
# (docs/console-protocol.md's "no expect directive" decision).
#
# Plain requests to the droid's own routes (keep GET /api/config, POST
# /api/config with a known value) are `http` steps, not pauses: they need the
# droid's address in --http-base, and the answers a row keeps (`> FILE`) land
# in --run-dir. A pause is left only where a person, a browser page, a flash
# or a value only this droid knows is needed.
#
# Run (serial is this board's primary transport; --http only if this board's
# own WiFi is up and reachable):
#   python3 tools/console_client.py --port /dev/ttyUSB0 --http-base http://10.0.0.22 \
#     --run-dir tasks/bench-run-artoo --script tools/bench_rows/artoo_esp32.txt
#
# Select rows (by name only, e.g. "safe-attach" -- not the ticket number):
#   --rows safe-attach,grouped-wifi-config   (explicit order, not file order)
#   --skip-manual                            (every row with no `pause` -- agent-runnable)
#
# After this ticket, #216 owns edits to this file (ticket body, "Rows").

# A2/A3/A4 (#338 #342 #345) - "Your calibration survives the move to addressed
# outputs", and there is only one place an endpoint is stored. The migration is
# the capability and it is ONE-SHOT per board: a pre-migration NVS crosses once,
# and A4 removes the legacy keys after the first successful save. The
# distinctive pre-migration values are set BEFORE the Wave 0 image is flashed;
# #355 carries that ordering and the numbers.
#
# The endpoints are NOT console-readable and no wording of this row can make
# them so: servo.status.current is is_query:false in the catalog -- a row that
# describes a field inside another response, never an independently executable
# command -- so it answers err/unavailable/not-executable, as it did on
# 2026-09-11. There is no servo.config.* operation either. Both reads are
# therefore GET /api/config, kept as an http step.
#

# configSaveServoOutputs() before configSave() (src/config_store.cpp), so an ordinary
# mode change IS a full config save and is what performs the migration. That is

# operator: the first save of ANY kind migrates. With both reads now http
# steps the row has no pause, so --skip-manual selects it: whether this
# board's NVS still holds a crossing to make is #355's to say, not the sheet's.
