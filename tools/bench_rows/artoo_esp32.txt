#   - The Console cannot SET a Component Member or an endpoint; those arrive on

# A7 (#340) - "Say which sound module is actually fitted, and change it later,
# rather than it being decided when the firmware was built." The CHANGE is the
# capability, so one reading proves nothing: read the lineup and the fitted
# member, change it, reboot, and hear which module answers.
@row 340 sound-member-survives-a-reboot
send system.api.get-components
send sound.status.current
send sound.action.play-track track=1
pause The audible half is Not Assessed at this bench - nothing is fitted, and sound.status.current reports link_ok:false device:none. Now POST /api/config with soundMember=<the other supported member id, e.g. mp3_trigger> - the write is accepted immediately and takes effect at reboot - then press Enter.
send system.action.reboot
pause Wait for the board to come back, re-attach, then press Enter
send system.api.get-components
send sound.status.current
send sound.action.play-track track=1

# A2/A3/A4 (#338 #342 #345) - "Your calibration survives the move to addressed
# outputs", and there is only one place an endpoint is stored. The migration is
# the capability and it is ONE-SHOT per board: a pre-migration NVS crosses once,
# and A4 removes the legacy keys after the first successful save. The
# distinctive pre-migration values are set BEFORE the Wave 0 image is flashed;
# #355 carries that ordering and the numbers.
#
# The endpoints are NOT console-readable and no wording of this row can make
# them so: servo.status.current is is_query:false in the catalog -- a row that
# describes a field inside another response, never an independently executable
# command -- so it answers err/unavailable/not-executable, as it did on
# 2026-09-11. There is no servo.config.* operation either. Both reads are
# therefore GET /api/config at a pause.
#
# system.action.set-mode is the SAVE. It calls saveConfigToNvs(), which runs
# configSaveServoOutputs() before configSave() (src/main.cpp), so an ordinary
# mode change IS a full config save and is what performs the migration. That is
# why "don't touch servo settings yet" is not sufficient guidance to a bench
# operator: the first save of ANY kind migrates.
@row 345 calibration-crosses-onto-the-rows
pause Fetch GET /api/config and keep the ten endpoint values for #355 - they must be the pre-migration numbers, not defaults. Press Enter.
send system.action.set-mode mode=stationary
send system.status.health
pause Fetch GET /api/config again. The first save has now run, so this is the post-migration read. Press Enter.

# A6 (#339) - "The controller says where it actually routes each signal." The
# Lane manifest is HTTP-only by design and the console cannot stand in for it:
# board_lanes is emitted by GET /api/identity alone
# (src/web/api_identity_serializers.cpp), while the console's
# system.api.get-identity deliberately answers with the two ConfigSnapshot
# fields and NOT the board manifest (consoleExecuteSystemApiGetIdentity,
# src/console/console_module.cpp). So the console sends prove the controller is
# up and answering as itself, and the lane evidence is fetched over HTTP at the
# pause -- the same split this sheet's header already uses for flash and heap
# figures that are read from /api/status rather than typed at the console.
@row 339 the-controller-says-where-it-routes
send system.api.get-identity
pause Fetch GET /api/identity from this board and keep the board_lanes object for #355, then press Enter
send system.status.health
